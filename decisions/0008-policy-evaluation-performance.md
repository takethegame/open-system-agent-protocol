# ADR-0008: 策略求值性能

- 状态：Provisional
- 日期：2026-11-19
- 关联：`docs/standard.md` §15.8、§6.9–§6.10、§7.11；`docs/roadmap.md` §M4

## 背景

如果每次上下文解析、每次消息路由、每次能力使用都重新跑完整策略，延迟会叠加到每个 Agent 跳转。用户会感觉“跨应用很慢”，实现者会用永久缓存或跳过策略来“优化”。需要给缓存与租约一个可审计的边界。

## 暂定结论

1. **缓存键必须完整**：策略缓存键至少包含 `user`、`agent`、`task_id`、`cap_id`、`action`、`resource`、数据标签、`policy_version`、`session_id`（若存在）。缺少任一维度都可能把一次授权复用到另一个任务。
2. **短租约**：缓存项 MUST 有 `expires_at` 与 `policy_version`；过期或版本变化 MUST 重新求值。L3/L4 的缓存租约 SHOULD 不超过 30 秒，并且每次执行前仍要检查撤销与回执状态。
3. **失败关闭**：策略引擎不可用、缓存损坏、版本未知时 MUST 返回 `deny`，不得使用“上次允许”。
4. **性能预算（进程内口径）**：在参考实现的本地策略路径上，缓存命中的 p95 SHOULD ≤ 5 ms，未命中的 p95 SHOULD ≤ 50 ms。该预算不是协议保证，机器、策略复杂度与审计写入会影响结果；实现 MUST 公布自己的测量口径。
5. **不优化掉审计**：策略求值可以缓存，但 L3/L4 的 `effect.intent`/`effect.executed` 与能力使用审计 MUST 照常写入；不得用“高频动作”作为跳过审计的理由。
6. **背压优先**：当策略引擎过载时，Bus SHOULD 返回 `RATE_LIMIT` 或 `TIMEOUT`，而不是无限排队；队列深度与 `retry_after_ms` 应可观测。

## 后果

- 缓存失效逻辑成为正确性关键；撤销、回执过期、策略升级都必须能失效相关缓存。
- L3/L4 的租约仍会带来短窗口；执行前撤销检查是兜底。
- 性能预算需要基准脚本与 CI 排除策略；当前撤销基准已因机器差异排除在 CI 外，策略基准也应同样处理。
- 不同实现的策略复杂度差异很大，跨实现比较必须说明口径。

## 备选方案

- **每次全量求值**：最正确，但延迟不可接受，且会鼓励绕过。
- **永久缓存**：最快，但无法表达撤销、过期与策略变更。
- **只缓存 allow**：减少误拒，但 allow 缓存被污染的风险更高；必须配合撤销检查。
- **把策略下推到 Bus**：减少一跳，但违反 Bus 不执行策略的职责分离。

## 重审触发条件

1. 参考实现或外部实现的 p95 超出预算，且不是机器差异导致；
2. 策略引擎更换，缓存键或版本语义变化；
3. 跨设备/企业策略引入远端求值，网络延迟成为主项；
4. 出现缓存导致的越权或跨任务复用事件。
